# 20: Coming soon and genre collections

Spec: [Reelio MVP spec](../../reelio-mvp/spec.md)

**What to build:** Discover gains Coming soon with real US opening dates and three genre collections that rotate daily. See the spec's Discover table rows 3 and 5–7.

**Blocked by:** [19: Discover homepage](./19-discover-homepage.md)

**Status:** resolved

- [x] Coming soon uses `discover` with `region=US`, theatrical and digital release types, US release dates from tomorrow to 60 days out; each Movie's US date comes from its `release_dates` (fetched with the payload) and shows as "Opens 21 Nov"; past or missing US dates are dropped
- [x] Three genre collections are picked each day, deterministically from the date, from the config list (Action, Comedy, Drama, Science Fiction, Horror, Animation, Thriller, Romance), each using `discover` by popularity with at least 300 votes
- [x] Both join the cross-section dedupe and failure rules, in the order Trending, Popular, Coming soon, Top rated, genres
- [x] Feature tests cover the date window, dropped dates, the deterministic rotation and dedupe

## Note from the build (2026-11-06)

- **Adapter.** `section()` now takes a neutral `SectionQuery` (`of(kind)`, `comingSoon(from, until)`, `genre(id, minimumVotes)`) instead of a bare `SectionKind`, since two lists need parameters. Coming soon reads `discover/movie` with `region=US`, `with_release_type=2|3|4` (limited theatrical, theatrical, digital), `release_date.gte/lte` and `sort_by=popularity.desc`; a genre collection reads `discover/movie` with `with_genres`, `vote_count.gte` and `sort_by=popularity.desc`, with no region. `MovieDetails` gains `usDigitalReleaseDate` (the earliest US type 4).
- **US date.** A Coming soon Movie's US date (`DiscoverMovie::opensOn`) is its US theatrical date as the Movie page reads it (type 3, else the earliest type 2), else its earliest US digital date. It comes from the detail call the background build already makes per Movie, so there's no separate `release_dates` call. That's up to 30 calls rather than the spec's "10 extra", because Movies are dropped for their dates. A Movie is kept only when that date falls from tomorrow to `discover.coming_soon.days_ahead` (60) days out (UTC), so a re-release or a past theatrical release now going digital is dropped. Dates past the window's end are dropped too, as the section is defined by the window. Candidates are looked up one at a time while the section fills, up to `discover.coming_soon.max_lookups` (30) per build, and no further page is read once that's used up, so dropped Movies can't eat the time budget of Top rated and the genres.
- **Coming soon failures.** A Movie whose details fail keeps the previous build's US date. If any lookup failed and nothing was kept, the section counts as failed and keeps its previous version, so a partial outage can't replace a good Coming soon with an empty one. A stored Coming soon Movie stops being shown once its US date is today or earlier, checked when reading, so a carried or un-rebuilt section never shows "Opens" for a past date. An interactive (first-visitor) build doesn't read Coming soon at all, because each Movie needs a detail call; the queued full build adds it.
- **Genre rotation.** Config `discover.genre_collections` holds the list by TMDB genre id, `per_day` (3) and `minimum_votes` (300). The day's picks are `per_day` consecutive entries starting at `(UTC day number × per_day) mod count`, so a pick is the same all day, consecutive days never share a genre with the default 8, and every genre gets equal turns. The day changes at 00:00 UTC; the 05:00 build is the first to use it, unless a visitor's build comes first.
- **Genre failures.** Sections are keyed by `DiscoverSection::key()` (the kind, or `genre-{id}`, which the page also uses as its key), and a genre section carries its genre (id and name, which titles it). Rotation means a failed collection rarely has a previous version for its own genre, so it keeps the previous build's collection for the same genre if there is one, otherwise the one in the same place, unless one of the day's own collections already covers that genre.
- **Builder.** Sections now resolve each candidate while filling (`collect()` takes a resolver), so a Movie the source no longer has makes room for the next instead of leaving a gap. The hero is the first Trending Movie with a backdrop and an overview; an interactive build details only that one.
- **Page.** Each section gets a page-unique `key` (`genre-878`), used for `:key`, `data-section` and the heading id, and a `title` (the genre name for collections). Coming soon rows carry `opensOn` and show "Opens 21 Nov" in place of the year, formatted in UTC so it doesn't slip a day in American time zones.
- **Budget.** Calls are still sequential. A full build is now about 70 detail calls (31 + up to 30 Coming soon lookups + 30 genre titles) plus around 7 to 21 list calls, inside the 45 s background budget at typical TMDB latency. Concurrency (ticket 19's note) is still the upgrade if that gets tight. Genre collections come last, so when the budget runs out they're the ones that fall back to previous details or versions.
- **After deploy.** A payload stored before this change has no Coming soon or genre sections, and visitors only rebuild an empty payload, so they appear with the next 05:00 UTC build, or sooner if `BuildDiscover` is dispatched by hand. A rollback to the previous release would drop every stored Movie, because the old `DiscoverMovie::fromArray` rejects the new `opensOn` key; the next visitor would then rebuild interactively.
